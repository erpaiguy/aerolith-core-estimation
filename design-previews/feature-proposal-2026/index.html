Aerolith Core Estimation · Proposal, not built

Making Aerolith behave like a document app for estimating

Excel is trusted because of three things that have nothing to do with formulas: a file you own, an edit loop you can always take back, and a save you can always reopen. Aerolith already has the estimating depth. These are the document-container behaviours it still needs.

Hard rule respected throughout: one .aero file never references another .aero file. Anything shared between jobs travels through the tenant global layer only.

Diagram 1 — The .aero document lifecyclepurple = proposed

The file loop: create, edit, review, seal, save, reopen

Today the loop breaks in two places — there is no way to undo an edit, and nothing survives a crash between saves.

Diagram 2 — Where linking is allowedthe rule that keeps .aero files portable

Files never link to files. Everything shared goes through the tenant global layer.

A job file must stay openable on a laptop that has never seen the other jobs. So a job takes a copy of anything global, stamped with the version it copied.

Build order

Phase 1 is the one that changes how the app feels. Everything after it is leverage on top of a file people already trust.

Phase 1 · Trust the fileNobody relaxes in a tool that can lose work
  • Undo / redo with named steps
  • Autosave journal and crash recovery
  • Unsaved-changes guard on close, open and switch
  • Save as, Save a copy, Revert to last save
  • Rolling backups, keep last 10
  • Document properties and integrity check
  • Schema version guard — refuse to silently damage a newer file
Phase 2 · Spreadsheet muscle memoryHands already know these moves
  • Range selection and Excel-fidelity copy / paste
  • Paste special — values, rates only, qty only
  • Fill down and fill series
  • Find and replace across a module
  • Sort and multi-column filter as a saved view
  • Column chooser, reorder, freeze panes
  • Selection stats in the status bar
  • Bulk operations: uplift %, round, swap unit
  • Number formats and conditional highlighting
Phase 3 · Estimating superpowersThe part no spreadsheet can do
  • Formula cells with a formula bar
  • Dependency inspector — precedents and dependents
  • Revision history inside the file, plus revision diff
  • Scenarios / what-if branches with side-by-side compare
  • Comments, review flags and sign-off
  • Cell-level change log with reasons
  • Attachments stored in the file
  • Lock and protect ranges
Phase 4 · Interchange and reuseOnly through the global layer
  • True multi-sheet XLSX export
  • XLSX round-trip — bring priced rates back by item key
  • Job and BOQ templates (.aerot)
  • Global assembly library with promotion
  • Price book with effective dates and refresh diff
  • Read-only and password-protected copies
  • Sealed submission packet with checksum
  • Where-used registry across the tenant
Foundation — blocks everything else Familiarity — cuts training to zero Differentiation — the reason to leave Excel Reach — plays nicely with the rest of the industry
