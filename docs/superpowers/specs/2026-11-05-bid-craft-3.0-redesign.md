# Bid Craft 3.0 redesign

Approved visual source: the packed mock `Bid Craft Enterprise Redesign`, screens **1–28 only**. Screens 29 and later are a different product and are not built.

## Product

- Name: Bid Craft. Publisher line: by Aerolith Core.
- App id: `com.aerolith.core`. Licence app id stays `aerolith-estimation`.
- Currency: QAR. Proprietary `UNLICENSED` licence. Nothing in this release uploads drawings, quantities, or rates.
- Scope: one tender at a time. The job file remains `.aero`. Calc kernel, BOQ, take-off, rate analysis, margins, licence, and updater stay the engines under the new shell.
- Version on every release surface: **3.0.0**. This branch does not run Publish Estimation release.

The shell is a **dark top bar**, an **ice rail**, and a **light canvas**. Primary actions are teal. Amber is the warning and in-progress accent. That is what the approved screens draw.

## Navigation

Workspace rail (no job, and library screens): Jobs, Reports, Masters, Settings, Owner console when the session is an owner, Sign out. Items that belong to screens 29+ (pipeline, calendar, clients, company library, benchmarks) stay visible with a **New** badge and do not open a screen.

Job rail, in this order:

1. Overview — Dashboard
2. Tender — Client queries (Documents and addenda, Contract review stay New and inert)
3. Measure — Client BOQ, Take-off
4. Price — Working BOQ, Rate analysis, Resource prices (Subcontract packages and Preliminaries stay New and inert)
5. Risk and money — Margins (Risk and contingency, Cash flow and bonds stay New and inert)
6. Submit — Submission BOQ, Finalise (Tender review, Qualifications and pack, Technical proposal stay New and inert)
7. After submission — both entries stay New and inert

Resource prices has working sub-pages: Project resources, Enquiries, Compare and choose for bid, Follow-up log. Escalation and currency stays inert.

The header has Jobs, File (open, save, close), a command field (Ctrl K), save state, and the signed-in person. Ctrl S saves the `.aero` file.

## Screens

| # | Screen | Behaviour |
| --- | --- | --- |
| 1 | Splash | Startup checklist, then sign-in. Version reads 3.0.0. |
| 2 | Sign in and licence | Email and password into the existing licence client. Offline copy explains the 14-day grace. Licence cards use the live session. Start trial and buy licence stay available. |
| 3 | Close job and sign out | Close asks to save, discard, or cancel. Sign-out shows the session summary, then returns to sign-in. |
| 4 | Landing | New job, open `.aero`, import, sample job, recent jobs, attention counts from the open catalogue and the current job. |
| 5 | New job wizard | Five steps: bid basis, job details, client BOQ import (existing extractor and column map), commercial defaults (margin stack), review and create. |
| 6 | Owner console | Tenant list, seats, licence state, issue or extend a licence, view-as-tenant. Audit still records impersonation. |
| 7 | Job dashboard | Direct cost, margin, working total, seal state, section bars, margin factors, attention links, resource cost tree from `costCategoryTree`. |
| 8 | Client BOQ | Issued lines for the focused bill. Import re-issue and amend open the wizard. Client quantities stay locked once the bill is locked. |
| 9 | Take-off | Lines for the selected item. Area, length, and count use the calc `qtoQty` formulas. Posting writes `ourQty` for that item. |
| 10 | Working BOQ | Filter, edit our qty and direct rate, open rate analysis, add or remove a line. Amounts come from `withResults`. |
| 11 | Rate analysis by cost category | Selected item’s build-up grouped by resource category. Edit qty, rate, and waste. Post returns to the working bill. |
| 12 | Margins | Overhead, profit, logistics, contingency as a percentage of direct cost. Reset restores the company default stack. Category amounts follow the job stack. |
| 13 | Client queries | Create, edit, answer, and close queries through `tenderQueries`. |
| 14 | Resource prices | Category rollup and resource rows. Edit the bid price. Open detail, enquiry, and compare. |
| 15 | Submission BOQ | Client quantities times submission rates, plus tender-adjustment rows where our qty differs. Grand total is the working total. Excel and PDF use the existing report export. |
| 16 | Finalise | Checks for unpriced lines, missing analysis, open queries, and total tie-out. Seal and new revision call the existing seal path. |
| 17 | Reports | Picks a packet and prints or exports it with the report engine. |
| 18 | Masters | Units, categories, vendors, and the project resource master. Promote and copy still use the tenant catalogue. |
| 19 | Settings | Currency and quantity policy, users and roles from the tenant, licence panel, updater check, backup compare. |
| 20 | Design system | Living specimen of the tokens, buttons, inputs, chips, empty state, error, and confirm. Reachable from Help. |
| 21 | Link or clone a rate | `linkWholeAnalysis` or `cloneWholeAnalysis` from a source item onto the target item. |
| 22 | Supplier enquiries | Draft and issue `EnquiryPack` rows on the job. Suppliers come from the vendor list. |
| 23 | Compare and choose | Quotes per resource. Lowest, one vendor, or a single line. `selectQuoteLine`, `selectLowestInLane`, and `applyVendorPack` write the bid price. |
| 24 | Follow-up log | Notes stored on the enquiry (`[follow-up …]` lines) so they save inside the `.aero` file with the job. |
| 25 | Rate analysis register | Every priced item, its source, direct cost, and rate. Open the build-up or the link screen. |
| 26 | Add or edit a component | One analysis line: resource, qty, unit, price, waste. Saved onto the item and recalculated. |
| 27 | Settings: cost categories | Edit `categories` (code and description). Order is the list order. |
| 28 | Resource detail | Code, description, category, type, unit, wastage, bid price, and quotes. Saving uses `applyResourceRate` when the price changes. |

## State

- Estimation results always pass through `withResults` before they are shown or saved.
- Enquiries, quotes, queries, analyses, margins, resources, and categories live on `LoadedProject` and round-trip through `.aero`.
- Follow-up lines are written into the enquiry notes so they stay with the job. No second database.
- Screens 29+ are not given routes.
